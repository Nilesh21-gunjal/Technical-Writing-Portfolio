# Docs-as-Code Best Practices

## Write for the task

Start with the user's goal, prerequisites, and a successful result. Put the action before background information when the reader needs to complete a task.

## Keep navigation predictable

- Use descriptive filenames.
- Keep heading levels sequential.
- Link each topic to the next logical topic.
- Test links after moving or renaming a file.

## Make procedures verifiable

Every procedure should include:

- Prerequisites
- Numbered steps
- Expected result
- Validation or troubleshooting guidance

## Review content in context

Use pull requests to review wording, code blocks, links, images, and information architecture together. Ask a subject-matter expert to verify technical behavior and terminology.

## Protect quality

Before publishing, check spelling, link targets, image alt text, command accuracy, version numbers, and sensitive information. Keep examples clearly fictional when they are not connected to a real service.
